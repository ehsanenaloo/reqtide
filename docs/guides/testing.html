Testing with the virtual clock

After this guide you can test retry, backoff, deadline and circuit behavior without sleeping and without flakiness: time moves only when you move it, every attempt returns what you script, and every event is recorded for assertions.

Applies to the unreleased alpha (no version number yet). Checked 2026-10-09 on PHP 8.3 to 8.5.

The helpers ship inside the single enaxon/reqtide package, in the Enaxon\Reqtide\Testing namespace (src/Testing). enaxon/reqtide is not on Packagist yet, so install it as described in Install. The helpers are for tests: never call them from production code. Every class is plain (no base test case) and marked @api-for-tests.

Every code block comes from examples/08-testing.php, which tools/run-examples.sh runs and compares with the recorded output. The example uses a small expect() function so it runs without a test framework; in a real suite use your framework's assertions.

What the helpers give you#

ClassPurpose
VirtualClockClock that moves only through advance(), advanceMonotonicOnly(), setMonotonic() (never backwards) and setWall(). Wall jumps are independent of the monotonic domain. failNextMonotonicReads(n) / failNextWallReads(n) inject ClockFailureException; read counts are observable.
SeededRandomSourceRandomSource over Random\Randomizer with an Mt19937 seed; same seed, same sequence.
ScriptedRandomSourceRandomSource returning a queued list of integers; records requested ranges and fails loudly when exhausted or out of range.
VirtualDelaySchedulerDelayScheduler (BoundedBlocking) that advances a VirtualClock instead of sleeping. Same checkpoint order as BoundedBlockingScheduler (deadline, then cancellation, then completion; equality is expired). cancelDuringNextDelay($token, $after) cancels mid-delay. Records every delay as a DelayRecord.
RecordingEventSinkEventSink storing events (events(), ofType()); throwOnEmit($e, $times) throws after recording, for failure-isolation tests.
ControlledRuntimeAdapterSynchronous RuntimeAdapter driven by DispatchScripts: return a value, throw, call the real operation, advance the virtual clock during the call, request cancellation during the call. Records dispatchCount(), attemptContexts() and dispatches() so tests assert observed dispatches.
DispatchScriptImmutable per-dispatch behaviour (returning, throwing, callingOperation, advancing, requestingCancellation).
ControlledExecutionThe settled RuntimeExecution the adapter returns. Observation: observed >= deadline is late (DeadlineExceeded, evaluated before cancellation); otherwise requested cancellation gives Cancelled; an unreadable clock gives null timing, incomplete accounting and a diagnostic. The actual outcome is always retained.
RecordingAttemptOperation / RecordingPreparedAttemptAttemptOperation counting prepare calls, rewinds() (prepares after the first), replay verifications, invocations and discarded outcomes; one-shot injected preparation and replay failures.
DispatchRecord, DelayRecordRead-only records exposed by the adapter and the scheduler.

Use one VirtualClock instance for the Deadline, the scheduler and the adapter; a Deadline rejects any other clock.

Step 1: Wire one virtual clock through everything#

Use one VirtualClock for the scheduler, the runtime adapter and the memory backends, so time only moves when you say so.

/** One VirtualClock drives the scheduler, the runtime and the memory backends, so time only moves when you say so. */
function rig(bool $withCircuit): array
{
    $clock = new VirtualClock();
    $scheduler = new VirtualDelayScheduler($clock);
    $runtime = new ControlledRuntimeAdapter($clock);
    $events = new RecordingEventSink();

    $builder = PipelineBuilder::profile('virtual-time', 'v1')
        ->partition('shop', 'test', 'orders-api')
        ->attemptTimeout(Duration::seconds(2), AttemptTimeoutRequirement::Cooperative)
        ->retry(4, BackoffMode::Exponential, Duration::milliseconds(100), Duration::seconds(1), JitterMode::None)
        ->retryBudget(10, 10, Duration::seconds(60), Duration::seconds(10));
    if ($withCircuit) {
        $builder = $builder->circuitBreaker(PipelineBuilder::lastCalls(2), 2, Ratio::of(1, 2), Duration::seconds(30), 1, 1, Duration::seconds(10));
    }

    $pipeline = $builder->compile(new RuntimeEnvironment(
        $clock,
        $scheduler,
        new SeededRandomSource(1),
        ExceptionClassifier::create()->retryOn(UpstreamTimeout::class),
        $runtime,
        $events,
        null,
        $withCircuit ? new MemoryCircuitBackend($clock) : null,
        null,
        new MemoryRetryBudgetBackend($clock),
        null,
    ));

    return [$pipeline, $clock, $scheduler, $runtime, $events];
}

InMemoryEnvironment (what compileInMemory() uses) wires the real clock and a scheduler that really sleeps, so a test builds the RuntimeEnvironment by hand as above. Never pair a VirtualClock with BoundedBlockingScheduler: it would wait for time that never passes.

Step 2: Anchor the context on the same clock#

/** A context whose deadline and replay-safety statement are both measured on the pipeline's (virtual) clock. */
function context(CompiledPipeline $pipeline, VirtualClock $clock): ExecutionContext
{
    $contract = ReplaySafetyContract::forReadOnlyCallable('get-order', Duration::seconds(3600), $clock);

    return $pipeline->newContext(Duration::seconds(10), OperationSafety::replayableRead($contract));
}

newContext() builds the deadline on the pipeline's own clock, so that part is automatic. Anything anchored to wall time, such as the replay-safety contract, must come from the same clock: a contract made from the real clock lies in the virtual clock's past or future and is treated as not valid (the retry is then denied and replay_contract_not_valid is recorded). A VirtualClock starts at a fixed date (2026-01-01T00:00:00+00:00 UTC) rather than the real time, so a test gives the same answer on every day; startingAt() picks another start.

Step 3: Test backoff without sleeping#

// The scripted runtime decides every outcome, so the callable you pass is never invoked here.
$unused = static fn(): string => throw new \LogicException('the scripted runtime replaces the callable');
[$pipeline, $clock, $scheduler, $runtime, $events] = rig(false);
$runtime->enqueue(
    DispatchScript::throwing(new UpstreamTimeout('503')),
    DispatchScript::throwing(new UpstreamTimeout('503')),
    DispatchScript::returning('ok'),
);
$start = $clock->peekMonotonic();
$result = $pipeline->execute($unused, context($pipeline, $clock));
$delays = array_map(static fn(Duration $d): int => intdiv($d->nanoseconds, 1_000_000), $scheduler->requestedDelays());

expect($result === 'ok', 'the third dispatch succeeds');
expect($runtime->dispatchCount() === 3, 'exactly three dispatches');
expect($delays === [100, 200], 'exponential backoff waited 100 ms, then 200 ms');
expect($clock->peekMonotonic() - $start === 300_000_000, 'the virtual clock moved by exactly those two delays');
expect(count($events->ofType(RetryScheduled::class)) === 2, 'two RetryScheduled events were recorded');

The first two scripted dispatches throw the retryable error, so the pipeline waits 100 ms and then 200 ms (exponential backoff, no jitter) and the third dispatch succeeds. The wait happened on the virtual clock: nothing slept.

Step 4: Test circuit recovery by advancing time#

[$pipeline, $clock, , $runtime] = rig(true);
$runtime->enqueue(
    DispatchScript::throwing(new \DomainException('down')),
    DispatchScript::throwing(new \DomainException('down')),
    DispatchScript::returning('recovered'),
);
for ($i = 0; $i < 2; ++$i) {
    try {
        $pipeline->execute($unused, context($pipeline, $clock));
    } catch (\DomainException) {
        // two failures open the circuit
    }
}
try {
    $pipeline->execute($unused, context($pipeline, $clock));
} catch (AdmissionRejectedException $e) {
    expect($e->reason()->value === 'circuit_open', 'the third call is refused while the circuit is open');
}
expect($runtime->dispatchCount() === 2, 'the refused call was never dispatched');

$clock->advance(Duration::seconds(31)); // no sleeping: time just moves
expect($pipeline->execute($unused, context($pipeline, $clock)) === 'recovered', 'a probe is admitted after the open duration');
expect($runtime->dispatchCount() === 3, 'the probe was dispatched');

Output of the whole script:

-- backoff without sleeping
ok: the third dispatch succeeds
ok: exactly three dispatches
ok: exponential backoff waited 100 ms, then 200 ms
ok: the virtual clock moved by exactly those two delays
ok: two RetryScheduled events were recorded
-- circuit recovery by advancing the clock
ok: the third call is refused while the circuit is open
ok: the refused call was never dispatched
ok: a probe is admitted after the open duration
ok: the probe was dispatched

Tips#

  • Seed randomness (SeededRandomSource) when you test jitter, and compare two runs with the same seed; assert the bound (full jitter stays between zero and the computed delay), not a hard-coded draw.
  • Assert on observed dispatches (dispatchCount()), not on what you think the pipeline did. A refused call must show zero dispatches.
  • Give each test a fresh pipeline. State lives in the backends, so a reused pipeline carries quota, budget and circuit state from one test into the next.

Limits#

A test that passes on virtual time shows that the policy logic does what you configured. It is not evidence about real timing, real transports or shared state. The helpers simulate settlement and delays; they do not model callback interruption or a physical transport stop.

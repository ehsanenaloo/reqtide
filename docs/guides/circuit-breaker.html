Circuit state lives in one PHP process. Under PHP-FPM a pipeline built inside a request starts every request with a closed circuit, and no request sees another's failures. See Limits and non-guarantees.

Code blocks come from examples/09-choosing-policies.php, which tools/run-examples.sh runs and compares with the recorded output. The numbers make behavior visible. They are not recommendations.

What a circuit breaker is for#

A dependency is down and callers keep hitting it. Every call waits, fails and adds load. The breaker watches the outcomes of recent calls. When too many failed, it opens and refuses new calls at once, without running your code. After a while it lets a few probe calls through to see whether the dependency has recovered.

Configure it#

The snippet below opens a circuit after repeated failures and shows what the fifth call gets. It also builds the same breaker over a time window.

Shared setup for the snippets on this page
/** Every pipeline below starts from the same two required options. */
$base = static fn(): PipelineBuilder => PipelineBuilder::profile('choosing', 'v1')
    ->partition('shop', 'prod', 'catalog-api')
    ->attemptTimeout(Duration::seconds(2), AttemptTimeoutRequirement::Cooperative);

$ok = static fn(): string => 'ok';
$context = static fn(CompiledPipeline $pipeline): ExecutionContext => $pipeline->newContext(Duration::seconds(30));
echo "-- 3. Circuit breaker: count window or time window\n";
$countWindow = PipelineBuilder::lastCalls(4);
$timeWindow = PipelineBuilder::timeWindow(Duration::seconds(60), Duration::seconds(5));
$pipeline = $base()
    ->circuitBreaker($countWindow, 4, Ratio::of(1, 2), Duration::seconds(30), 1, 1, Duration::seconds(10))
    ->compileInMemory(ExceptionClassifier::create());
$invoked = 0;
$broken = static function () use (&$invoked): string {
    ++$invoked;

    throw new \DomainException('down');
};
for ($i = 1; $i <= 5; ++$i) {
    try {
        $pipeline->execute($broken, $context($pipeline));
    } catch (\DomainException) {
        // Closed circuit: your exception comes through.
    } catch (AdmissionRejectedException $e) {
        echo "call {$i} refused with {$e->reason()->value}; the callable ran {$invoked} times\n";
    }
}
// The same breaker over a 60 s window split into 5 s buckets.
$timeBased = $base()
    ->circuitBreaker($timeWindow, 4, Ratio::of(1, 2), Duration::seconds(30), 1, 1, Duration::seconds(10))
    ->compileInMemory(ExceptionClassifier::create());
echo 'time-window circuit compiled: ', $timeBased->explain()->profileId->value, "\n";
-- 3. Circuit breaker: count window or time window
call 5 refused with circuit_open; the callable ran 4 times
time-window circuit compiled: choosing

While the circuit is closed, your own exception comes through unchanged (the empty catch above). Once it is open, the call is refused with AdmissionRejectedException and reason circuit_open, and the callable runs no more: four invocations in total. A refused call never reaches your callable, and the refusal is not a sample.

Read the arguments in order#

circuitBreaker(window, minimumSamples, failureThreshold, openDuration, probeCapacity, probeSuccessThreshold, permitLease):

ArgumentMeaning
windowlastCalls(n) keeps the last n completed non-neutral outcomes. timeWindow(window, bucketGranularity) aggregates outcomes in buckets and is approximate at its boundary.
minimumSamplesHow many outcomes must exist before the circuit may open. It cannot exceed a count window.
failureThresholdThe failure share at which it opens, as a Ratio, for example Ratio::of(1, 2) for half.
openDurationHow long it stays open before it admits probes.
probeCapacityHow many probe calls may be in flight when it is half-open.
probeSuccessThresholdHow many successful probes close it. It cannot exceed the probe capacity.
permitLeaseHow long a call's permit stays valid. It must exceed the attempt timeout by more than 1 second.

Closed, open, half-open#

  • Closed. Calls pass, and each completed outcome is recorded in the window. When the window holds at least minimumSamples and the share of failures reaches the threshold, the circuit opens.
  • Open. Calls are refused with circuit_open. After openDuration the circuit becomes half-open.
  • Half-open. Up to probeCapacity probes are admitted. It closes after probeSuccessThreshold successful probes. A failed probe reopens it at once, and a refused call (circuit_probe_capacity_exhausted) is not a sample.

The circuit is safe against stale or lost results. A probe that is abandoned or expires frees its slot without counting as success or failure, and a result that arrives after the circuit reopened cannot change its state. Every permit ends exactly once: on success, on exception and on cancellation. The circuit emits a CircuitTransitioned event on every change (API reference).

What counts as a failure#

Your classifier decides. With ExceptionClassifier:

  • every exception counts as a circuit failure, unless you list its class in ignoreForCircuit(), for example your own validation error, which says nothing about the dependency;
  • once you give a countAsCircuitFailure() list, only the listed classes (and retryable ones) are failures, and every other exception is circuit-neutral;
  • unacceptableValuesWhen() marks a returned value as a failure, for example an error payload returned with a normal status;
  • refusals by other protections, cancellations and storage errors are neutral: they neither open nor heal the circuit.

A call that settles after the operation deadline is neutral too: the caller already got DeadlineExceeded, and the late result says nothing about the dependency that the circuit may act on. Give the callable its own timeout shorter than the pipeline deadline, so that a slow dependency fails inside the deadline and counts. Slow-call counting, as an option, is planned for a later release.

An exception nobody listed counts as a failure, because a circuit that ignored unknown failures would stay closed against a dependency that fails in a way nobody anticipated.

Testing recovery#

A test of "open, wait 30 seconds, probe, close" should not wait 30 seconds. Move a virtual clock: see Testing with the virtual clock.

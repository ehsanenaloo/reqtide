How to read this page#

The types of the core package live under the namespace Enaxon\Reqtide; each heading shows the namespace after the class name. The last four groups on this page list classes of two separate packages, enaxon/reqtide-redis (namespace Enaxon\Reqtide\Redis) and enaxon/reqtide-guzzle (namespace Enaxon\Reqtide\Guzzle). Those packages are not released and not part of the core archive. Listings show the public surface in source order: constructors, public properties, enum cases and public methods. Members marked @internal in the source are left out. Parameter types are shown without namespaces.

NamespaceWhat it holds
PipelineThe builder, the compiled pipeline and the in-memory environment.
Execution, FallbackPer-operation context, the safety statement and the fallback contract.
OutcomeClassifiers and the verdicts they return.
Policy, ValueOption enums and objects, Duration and Ratio.
CompletionThe result of detailed execution.
Error, ExceptionReasonCode, Problem and the typed exceptions.
TelemetryTyped events and the sink contract.
TestingTest helpers, shipped in the same package.
RedisShared state on Redis. Separate package enaxon/reqtide-redis. See Shared state with Redis.
GuzzleGuzzle integration. Separate package enaxon/reqtide-guzzle. See Guzzle requests with Reqtide.

Lower-level extension points are not listed here yet: the state backends in State, the runtime adapters in Runtime, the clocks and schedulers in Time, and the identifier value types. They exist in src/ for hand-built environments, such as the one in Testing with the virtual clock.

The shortest path through the surface#

  1. PipelineBuilder::profile(), then partition(), attemptTimeout() and any policy methods, then compileInMemory($classifier).
  2. $pipeline->newContext(Duration $timeout, ...) for each operation.
  3. $pipeline->execute($callable, $context) for a value or an exception, or executeDetailed() for an ExecutionCompletion.

Start with Getting started if you have not run that sequence yet.

Build a pipeline#

Everything you need at start-up. PipelineBuilder assembles and validates the configuration, compileInMemory() wires process-local state, and the result is a CompiledPipeline you reuse. Every number is yours: the builder has no defaults.

PipelineBuilder Enaxon\Reqtide\Pipeline

Fluent, immutable builder: every call returns a new builder. profile(), partition() and attemptTimeout() are required; a policy exists only if you call its method. A bad value raises InvalidConfigurationException naming the option.

final class PipelineBuilder {

    public function partition(
        string $application,
        string $environment,
        string $subject,
        ?string $tenant = null,
    ): self;
    public function attemptTimeout(
        Duration $maximumDuration,

    ): self;
    public function retry(
        int $maxAttempts,
        BackoffMode $backoff,
        Duration $baseDelay,
        Duration $maximumDelay,
        JitterMode $jitter,
        ?Duration $minimumRemainingAttemptAllowance = null,
    ): self;
    public function retryBudget(
        int $capacityTokens,
        int $refillTokens,
        Duration $refillInterval,
        Duration $reservationLease,
    ): self;
    public function rateLimit(
        RateAlgorithmOptions $algorithm,
        int $cost = 1,

    public function circuitBreaker(
        CircuitWindowOptions $window,
        int $minimumSamples,

    public function cooldown(

    public function fallbackScope(FallbackScope $scope): self;
    public static function tokenBucket(
        int $capacity,
        int $refillTokens,
        Duration $refillInterval,
    ): TokenBucketOptions;
    public static function fixedWindow(
        int $capacity,

    public static function slidingWindow(

        Duration $window,

profile()
Names and versions the configuration. Change the version when settings change; shared state is keyed by it.
partition()
Whose state this is: application, environment, subject and an optional tenant. One pipeline serves exactly one partition.
attemptTimeout()
The longest one attempt may take. Use Cooperative with the synchronous runtime.
retry()
Up to maxAttempts attempts, the first included. More than one needs retryBudget() and a replay-safety assertion on every call.
retryBudget()
A token pool that pays for retries so a failing dependency is not hammered.
rateLimit()
Charges cost units per dispatch, retries included. Takes the result of tokenBucket(), fixedWindow() or slidingWindow().
circuitBreaker()
Judges a window of completed calls, opens at a failure share, probes after the open duration.
bulkhead()
At most capacity operations in flight; lease bounds a slot whose owner vanished.
cooldown()
A shared pause after a server-stated wait. Needs a classifier that reports waits.
fallbackScope()
Whether a fallback may also replace admission refusals.
tokenBucket()
Rate algorithm: capacity, refill tokens per interval.
fixedWindow()
Rate algorithm: capacity per window, aligned to the epoch or to the first hit.
slidingWindow()
Rate algorithm: an approximate sliding counter.
lastCalls()
Circuit window over the last N completed calls.
timeWindow()
Circuit window over a duration, kept in buckets.
definition()
Validates the composition and returns the immutable PipelineDefinition.
compile()
Compiles against a hand-built RuntimeEnvironment, for example with test helpers.
compileInMemory()
Compiles with the real clock, sleeping delays and process-local memory backends. There is no default classifier.

CompiledPipeline Enaxon\Reqtide\Pipeline

The reusable pipeline. It holds the state that makes limits work, so build it once and share it. It has no per-operation state.

final class CompiledPipeline {
    public function newContext(
        Duration $timeout,
        ?OperationSafety $safety = null,
        ?FallbackOperation $fallback = null,
        ?Cancellation $cancellation = null,
        ?BoundedMetadata $attributes = null,
        OperationId|string|null $operationId = null,
        ?PartitionIdentity $partition = null,
    ): ExecutionContext;
    public function execute(
        callable $operation,
        ExecutionContext $context,
    ): mixed;
    public function executeDetailed(
        callable $operation,
        ExecutionContext $context,
    ): ExecutionCompletion;
    public function executeOperation(
        AttemptOperation $operation,
        ExecutionContext $context,
    ): mixed;
    public function executeOperationDetailed(
        AttemptOperation $operation,
        ExecutionContext $context,
    ): ExecutionCompletion;
    public function explain(): PipelineExplanation;
}
newContext()
One context per operation: the total deadline, the replay-safety statement, an optional fallback, cancellation and an operation id.
execute()
Runs a callable through the pipeline. Returns your value, throws your own exception unchanged, or throws a Reqtide refusal.
executeDetailed()
Same run, but returns an ExecutionCompletion instead of throwing for business or policy outcomes.
executeOperation()
Like execute() for an AttemptOperation object instead of a callable.
executeOperationDetailed()
Like executeDetailed() for an AttemptOperation.
explain()
Describes the configured policies and the runtime capabilities. No I/O and no state change.

OperationSafety Enaxon\Reqtide\Execution

Your statement about repeating a call. unsafe() is the default and forbids retries; the other two allow them.

final readonly class OperationSafety {

    public static function replayableRead(ReplaySafetyContract $contract): self;
    public static function providerIdempotentMutation(

    ): self;
}
unsafe()
The default. A pipeline that allows more than one attempt refuses to run.
replayableRead()
You assert that running the callable again is safe.
providerIdempotentMutation()
You assert that the provider deduplicates repeated mutations.

Decide what an outcome means#

Policies act on the classification of each attempt, and you decide what a failure is. ExceptionClassifier is the ready-made classifier; implement OutcomeClassifier for anything it cannot express.

ExceptionClassifier Enaxon\Reqtide\Outcome

Classifier driven by lists of exception classes. Conservative on purpose: an exception nobody listed is not retried and not replaced by a fallback, but it counts as a circuit failure. Matching is instanceof. Every method returns a new instance.

final readonly class ExceptionClassifier implements OutcomeClassifier {
    public static function create(): self;
    public function retryOn(string ...$exceptionClasses): self;
    public function countAsCircuitFailure(string ...$exceptionClasses): self;
    public function ignoreForCircuit(string ...$exceptionClasses): self;
    public function fallbackOn(string ...$exceptionClasses): self;
    public function retryAfterFrom(callable $extractor): self;
    public function unacceptableValuesWhen(callable $predicate): self;
    public function classify(
        Outcome $outcome,
        OperationMetadata $metadata,
    ): OutcomeClassification;
}
create()
An empty classifier.
retryOn()
Exception classes that may be retried.
countAsCircuitFailure()
Narrows circuit failures to these classes (and retryable ones). Without it every exception that is not ignored counts.
ignoreForCircuit()
Exception classes that say nothing about the dependency, such as validation errors. Ignore wins over a failure list.
fallbackOn()
Exception classes a fallback may replace.
retryAfterFrom()
Extracts a server-stated wait (a Duration or null) from an exception.
unacceptableValuesWhen()
Marks a returned value as a failure: a circuit failure, never retried, never replaced.
classify()
The OutcomeClassifier contract.

Errors and reasons#

Your own exceptions come out unwrapped. A Reqtide decision is a typed exception that implements ProblemCarrier. Branch on reason() and problem(), never on message text.

Problem Enaxon\Reqtide\Error

Immutable, redaction-safe report shaped after RFC 9457 problem details. It is built from code metadata only: no message, URL, header or credential can enter it. Member names and order are API; title and detail wording is not.

HttpOperation Enaxon\Reqtide\Guzzle

One logical HTTP operation: an absolute request and your explicit statement of whether and how it may be sent again. Nothing is guessed from the method or a header.

final readonly class HttpOperation {
    public const DEFAULT_MAX_VERIFIED_BODY_BYTES = 16777216;
    public ?Closure $bodyFactory;
    public function forClient(GuzzleConfiguration $configuration): self;
    public static function read(
        RequestInterface $request,
        string $operationGroup,
        Duration $validFor,
        array $retryableOutcomeCodes = [],
        ?Closure $bodyFactory = null,
        ?Clock $clock = null,
        ?string $credentialKey = null,
        BodyIntegrity $bodyIntegrity = BodyIntegrity::Verified,
        int $maxVerifiedBodyBytes = self::DEFAULT_MAX_VERIFIED_BODY_BYTES,
    ): self;
    public static function idempotentMutation(
        RequestInterface $request,
        string $operationGroup,
        string $identityValue,
        string $identityScope,
        string $duplicateHandling,
        Duration $validFor,
        ?Duration $retention = null,
        ?string $identityHeader = 'Idempotency-Key',
        array $retryableOutcomeCodes = [],
        ?Closure $bodyFactory = null,
        ?Clock $clock = null,
        ?string $credentialKey = null,
        BodyIntegrity $bodyIntegrity = BodyIntegrity::Verified,
        int $maxVerifiedBodyBytes = self::DEFAULT_MAX_VERIFIED_BODY_BYTES,
    ): self;
    public static function single(
        RequestInterface $request,
        string $operationGroup,
        ?string $credentialKey = null,
    ): self;
    public function metadata(): OperationMetadata;
}
read()
For GET and HEAD. You state that repeating the request has no side effect, for how long, and which outcomes may be retried.
idempotentMutation()
For POST, PUT, PATCH or DELETE that the server deduplicates by an identity. The same body and the same identity are sent on every attempt, and the identity is checked before each one.
single()
Sent once, never repeated. Core refuses it in a pipeline that retries more than once.
metadata()
The bounded facts passed to the pipeline: the safety statement and the descriptor attributes.

HttpOutcomeClassifier Enaxon\Reqtide\Guzzle

Decides which statuses and cURL errors are retried, count against a circuit, may fall back or set a cooldown. Every method returns a new instance.

final readonly class HttpOutcomeClassifier implements OutcomeClassifier {
    public static function starter(?Clock $clock = null): self;
    public static function empty(?Clock $clock = null): self;
    public function withRetryableStatuses(int ...$statuses): self;
    public function withCircuitFailureStatuses(int ...$statuses): self;
    public function withCircuitNeutralStatuses(int ...$statuses): self;
    public function withFallbackStatuses(int ...$statuses): self;
    public function withRetryAfterStatuses(int ...$statuses): self;
    public function withRetryableTransportErrnos(int ...$errnos): self;
    public function retryableOutcomeCodes(): array;
    public function classify(
        Outcome $outcome,
        OperationMetadata $metadata,
    ): OutcomeClassification;
}
starter()
A documented starting set. It is not a recommendation for every API.
empty()
Retries and falls back on nothing and reads no Retry-After.
retryableOutcomeCodes()
The reason codes that can be retried. Pass them to read() and idempotentMutation(). An empty list never retries.

PHP resilience toolkit · Documentation

One pipeline between your code and an unreliable API.

Reqtide wraps a callable with a total deadline, retries paid from a budget, a rate limit, a circuit breaker, a bulkhead and an optional fallback. Failures come back as typed results, and tests run on a virtual clock without sleeping.

Build a first pipeline →Browse all guides

Free and open source (MIT). Alpha: not released, not on Packagist. The core package keeps state in one process.

What you get

  • One total deadline across attempts, delays and fallback
  • Retries that need your safety statement and a retry budget
  • A rate limit in three algorithms, charged on every dispatch
  • A circuit breaker and a bulkhead with leased permits
  • Typed errors: a stable ReasonCode and a redacted Problem
  • A virtual clock and scripted attempts for tests that never sleep

What is built, and what is planned

The core package enaxon/reqtide keeps its state in one PHP process. Shared state in Redis (enaxon/reqtide-redis) and a Guzzle integration (enaxon/reqtide-guzzle) exist as separate packages in the development repository. They are not released and not on Packagist, and they were run only in local Docker: PHP 8.3 to 8.5 on the command line, Redis 7.4.11 and 8.2.10, Guzzle 7.15.5. PHP-FPM, Redis Sentinel, Redis Cluster, Valkey and PSR-18 are not supported. Webhook delivery and headless-CMS recipes are ideas only. A plan is not a promise. Limits and non-guarantees lists what the alpha does not do.
